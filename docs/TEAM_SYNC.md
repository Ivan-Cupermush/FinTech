## Как работают два чата

`/synk` — договорённость в чате. Получив её, агент делает следующее:

1. Проверяет локальные изменения, выполняет `git fetch origin --prune`, читает `git show origin/codex/team-sync:docs/TEAM_SYNC.md`, смотрит открытые PR и изменения в `origin/main`. Рабочую папку коллеги с незакоммиченными файлами оставляет на месте.
2. Сопоставляет карточки с фактическими ветками, коммитами, состоянием PR и проверок. Обновляет свои записи при расхождениях. Возвращает краткую сводку: что изменилось, кто чем занят, что ждёт решения, откуда продолжать.
3. Новый запрос пользователя сразу записывает в журнал, сохраняя условия, критерии приёмки и отложенные части. Уточняет автора, если это существенно. Пароли, ключи, персональные данные интервьюируемых и закрытые ссылки в журнал не попадают.
4. Перед началом публикует заявку на свободную задачу: ID, владелец (человек и чат), границы работы, затрагиваемые файлы и следующий шаг. Если два чата берут один ID, владельцем становится тот, чей коммит первым принят GitHub. Второй перечитывает запись и выбирает свободную задачу либо согласует разделение файлов.
5. Для записи использует отдельную рабочую копию ветки журнала. Перед правкой подтягивает её через fast-forward. Коммитит только журнал и сразу выполняет обычный push в `codex/team-sync`. При отказе push перечитывает удалённые изменения и переносит свою запись поверх них с сохранением чужих. При гонке за один ID снимает свою проигравшую заявку. Force-push исключён. Пока push не принят, коллега запись не видит.
6. Публикует обновление при смене решения, появлении проверяемого результата, блокировке и перед завершением сессии. Код ведёт от актуального main в отдельной ветке через PR. В журнале оставляет ссылки на PR, коммиты и артефакты, результат проверок и конкретный следующий шаг. Владелец явно передаёт задачу. При неожиданном обрыве второй чат проверяет ветку, PR и доступные артефакты и согласует перехват с человеком. Чужие незапушенные файлы на другом ПК из GitHub недоступны.

**Карточка для копирования:** ID и название · исходная просьба и ограничения · ожидаемый результат · статус · владелец/чат · дата и время с поясом · область файлов · ветка/PR/артефакт · решения и открытые вопросы · что проверено · следующий шаг. Историю важных решений дописываем под карточкой.
