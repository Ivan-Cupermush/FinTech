# Offix — материалы для согласования

## Навигация сайта и приложения

На сайте шесть главных разделов: **Задачи**, **Цели**, **KPI**, **Чаты**, **Совещания**, **Настройки**. В «Задачах» по умолчанию открывается список «Мои текущие» с группами «Сегодня», «Просрочено» и «Позже». На телефоне вариант A оставляет четыре быстрые вкладки и открывает «Совещания» и «Настройки» из «Ещё». Вариант B даёт совещаниям отдельную быструю вкладку, а настройки открывает через профиль. Рекомендация: боковая панель A на сайте и нижняя панель B в приложении, если совещания действительно становятся еженедельным сценарием. До появления совещаний можно оставить на телефоне четыре пункта и профиль в шапке. Внутреннее устройство чатов сохраняется.

| Сейчас | Предлагаемый вход |
|---|---|
| Пульс | «Задачи» показывает ближайшие действия, «Цели» — статусы целей |
| Эффект и отчёт | «KPI» → результаты и отчёт. Экран существующего эффекта сохраняет отдельное представление |
| База знаний и помощник | «Цели» → материалы цели, общая база доступна из поиска в шапке |
| Мои заметки | «Задачи» → личные заметки и быстрый переход из профиля |
| Продажи | «KPI» → продажи для пользователей, которым доступен модуль |
| Организация | «Настройки» → команда и структура с действующими правами |
| Интеграции, функции компании, безопасность | «Настройки» → управление компанией с действующими правами |
| Уведомления | Колокольчик в шапке и настройки уведомлений в профиле |

Критерий для следующего прототипа: пользователь с телефона и с сайта заходит в активную задачу, определяет причину риска по цели, находит материалы встречи и открывает каждую перенесённую функцию. Проверяем на обычной и администраторской ролях.

## Цель

После заголовка и краткого статуса сразу виден граф. Узлы группируются в колонки «Факторы», «Показатели», «Цель». Линии идут между карточками, обходят подписи, а круглая точка обозначает соединение. В неизбежной точке пересечения одна линия проходит мостиком без точки. При выборе узла подсвечивается его цепочка. Стрелку и связь можно проверить на клавиатуре через список зависимостей. На телефоне сначала видна выбранная цепочка, рядом кнопка «Весь граф» для изучения полной схемы. Под графом всегда видна последовательность «показатель → причина риска → следующее действие», например «7 дней → очередь на проверку → назначить ответственного». Материалы, история и полная дорожная карта доступны ниже. Статус читается по тексту и значку.

## Совещания

1. **Назначение и архив.** Организатор выбирает тему, время, участников, формат и при необходимости ссылку. Список «Предстоящие / Прошедшие» ведёт в карточку встречи. Карточка хранит запись, транскрипт с таймкодами, тезисы, решения и черновики, привязанные к одной встрече.
2. **Запись и расшифровка.** Перед стартом явное уведомление, во время записи видимый индикатор и кнопка остановки. Для первой версии полезны загрузка файла и запись с явно выбранного источника звука. Запись микрофона браузера не гарантирует захват голосов из другой вкладки или приложения. Содержание доступно участникам согласно правам, организатор управляет выдачей доступа. Срок хранения, удаление и порядок согласия следует утвердить до запуска на реальных встречах.
3. **Обработка.** Отдельный сервис распознавания речи выдаёт сегменты с таймкодами. Генератор получает текст в контексте конкретной встречи, возвращает короткие тезисы, решения и предлагаемые действия со ссылкой на исходный сегмент. Для каждой задачи сохраняются описание, подтверждённые назначение и срок либо пустые поля. Участник редактирует и подтверждает черновик до создания задачи. Фоновая обработка показывает этап и позволяет повторить сбойный шаг. Доступ к материалам изолирован по компании и участникам.
4. **Во время встречи.** Сначала ручные черновики. Затем промежуточная транскрипция и предложения по завершённым фрагментам. На финальной обработке объединяем повторяющиеся предложения и сохраняем уже подтверждённые задачи. Пилот проверяет русскую речь, шум, перебивания, качество таймкодов и долю пригодных черновиков.
5. **Видео.** На первом этапе удобно добавить внешнюю ссылку в приглашение. Встроенную комнату разумно пилотировать на готовом WebRTC SDK с управляемым либо собственным SFU. Для группового звонка потребуются сигнализация, обход NAT через TURN, токены комнат, совместимость браузеров и Expo, переподключение, демонстрация экрана, мониторинг, отдельный контур записи и хранение. По сложности: подключить ссылку просто, встроить надёжную комнату с SDK — отдельный проект средней или высокой сложности, собственный стек и серверная запись — высокая. Перед оценкой срока нужны размер групп, число одновременных встреч, браузеры и требования к размещению аудио и видео.

### ИИ offix

База знаний имеет два режима. Встроенный режим ищет по документам и возвращает цитаты. Генерацию текста выполняет Ollama, если модель настроена и доступна. Для совещаний можно переиспользовать интерфейс генерации с отдельным серверным обработчиком, настройками доступа, разбиением длинных транскриптов и проверкой структуры результата. Распознавание аудио — самостоятельный компонент. Содержимое совещаний не индексируем автоматически в общей базе знаний. В облачном демо проверены авторизованные запросы к статусу базы знаний и вопросу: builtin, ready=true, без модели, ответ с четырьмя источниками. Все 23 теста базы знаний прошли. Локальный Ollama на стандартном порту не ответил. Режим рабочего стенда нужно подтвердить там через авторизованный статус базы знаний и контрольный запрос к модели. Для запуска пилота используем вымышленную запись.
