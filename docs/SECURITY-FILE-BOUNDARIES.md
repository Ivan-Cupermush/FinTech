# SEC-02 — доступ к файлам и сведениям базы знаний

## Изменение поведения

Оригиналы и превью вложений доступны по подписанному URL, выданному конкретному пользователю. Каждый запрос к URL повторно проверяет активность пользователя, членство в организации, актуальную роль и видимость объекта, к которому прикреплён файл. Подпись сама по себе больше не сохраняет доступ после исключения из чата или скрытия сообщения пользователем. Для оригинала, превью, HEAD, Range и условного запроса действует одна проверка.

Ранее превью выдавались по постоянному случайному имени без проверки роли. Новые ответы API содержат thumb_url через подписанный маршрут оригинала с preview=1. Старый маршрут /files/thumbs/:name закрыт. Уже существующие вложения используют новый маршрут при получении свежего ответа API. Старому открытому экрану потребуется заново получить список вложений. Аватары сохраняют прежний публичный маршрут.

Ответы защищённых файлов используют private, no-cache, no-transform. Браузер должен перепроверить доступ перед повторным использованием сохранённого ответа. Уже скачанное содержимое и ранее закэшированные старые ответы нельзя отозвать с устройства получателя. Подписанный URL остаётся временной ссылкой доступа, его нельзя передавать посторонним.

Статус базы знаний считает фрагменты только из доступных пользователю материалов, с тем же ограничением по целям, которое использует поиск. Счётчик больше не растёт при загрузке документа скрытой цели.

## Воспроизведение и проверка

На исходной версии новые проверки воспроизвели два расхождения:

- после исключения из чата GET карточки вложения возвращал 404, но выданный ранее URL оригинала возвращал 200;
- число фрагментов для сотрудника увеличивалось после добавления документа недоступной ему цели.

server/test/media.test.ts проверяет доступ к оригиналу и превью до исключения, отказ после него, HEAD, Range и условный запрос, закрытый старый маршрут превью, а также отказ по прежнему URL после удаления сообщения «у себя». Обычная выдача превью и работа с файлами остаются в прежних тестах.

server/test/knowledge.test.ts проверяет, что закрытый документ отсутствует в списке, карточке, ответах помощника, доступе к файлу и счётчике. Остальные тесты безопасности проверяют отдельную организацию, отключённых пользователей и личную выгрузку. Эти результаты подтверждают конкретные сценарии; полный аудит всех маршрутов продолжается по плану.

## Что показать на защите

На синтетическом наборе открыть вложение у двух участников. Исключить одного из группы. По сохранённому URL у исключённого участника оригинал и превью получают отказ; другой участник продолжает открывать вложение. Затем показать, что документ закрытой цели не меняет доступную сотруднику статистику базы знаний. В протоколе указать SHA, пользователей и результаты запросов.
